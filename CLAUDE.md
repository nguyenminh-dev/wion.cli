## Project Overview

This repository contains two main components:

1. **Wion.Cli** - A .NET 6.0 command-line tool that generates new ABP-based projects from a template
2. **Wion.Template** - An ABP Framework 5.2.2 layered template solution used as the source for project generation

The CLI copies `Wion.Template`, replaces all occurrences of "Wion.Template" with the target project name, and produces a ready-to-use ABP solution.

## Build Commands

### CLI (Wion.Cli)

```powershell
# Build the CLI
.\build.ps1 Build

# Publish to deployable output
.\build.ps1 Publish

# Clean build artifacts
.\build.ps1 Clean

# Run tests
.\build.ps1 Test

# Direct dotnet commands
dotnet build Wion.Cli\Wion.Cli.csproj
dotnet test Wion.Cli\Wion.Cli.csproj
```

After publishing, add `Wion.Cli\bin\Release\net6.0\publish` to PATH to use `wion` command globally.

### Generated Projects

Projects generated by `wion new` target .NET 6.0 and ABP Framework 5.2.2. To build a generated project:

```powershell
cd <GeneratedProject>
dotnet restore
dotnet build
```

## CLI Architecture

The CLI follows clean architecture with separation of concerns:

- **Program.cs** - Entry point, initializes System.CommandLine
- **Commands/NewCommand.cs** - Handles `wion new` command, validates input, creates TemplateProcessor
- **TemplateProcessor.cs** - Orchestrates the 4-step generation process:
  1. Copy directory structure (with rename during copy)
  2. Process file contents (replace "Wion.Template" → new name)
  3. Rename remaining directories (deepest first to avoid path conflicts)
  4. Rename files
- **Services/FileReplacer.cs** - Handles content replacement, skips binary files
- **Services/DirectoryRenamer.cs** - Handles file/directory renaming with collision detection
- **Services/Logger.cs** - Logging with verbose mode support

**Processing order matters**: Directories are renamed deepest-first to prevent path conflicts during renaming. Binary files are detected by extension and skipped during content replacement.

## Template Architecture

Wion.Template is a standard ABP layered application with these modules:

**Core Layers:**
- `Domain` - Entities, value objects, domain services
- `Domain.Shared` - Constants, enums, shared definitions
- `Application` - Application services, DTOs, business logic orchestration
- `Application.Contracts` - DTOs, interfaces for API contracts
- `EntityFrameworkCore` - DbContext, EF Core mappings, migrations

**Hosting:**
- `HttpApi.Host` - ASP.NET Core API host (includes OpenIddict, authentication)
- `DbMigrator` - Console app for database migrations and data seeding

**Tests:**
- `TestBase` - Shared test infrastructure
- `Domain.Tests`, `Application.Tests`, `EntityFrameworkCore.Tests` - Layer-specific tests

The template uses xUnit, NSubstitute, and Shouldly for testing.

## Running Generated Projects

Before running a generated project for the first time:

```powershell
# Install ABP client-side libraries
abp install-libs

# Run database migrator (creates database, seeds initial data)
dotnet run --project src/<ProjectName>.DbMigrator

# Run the API host
dotnet run --project src/<ProjectName>.HttpApi.Host
```

Configure connection strings in `appsettings.json` under `HttpApi.Host` and `DbMigrator` projects before first run.

## Important Constraints

- **All projects target .NET 6.0** - Do not upgrade to .NET 9.0
- **ABP Framework version 5.2.2** - Pin to this version
- **UTF-8 encoding** - All file processing uses UTF-8
- **Binary file extensions skipped**: `.dll`, `.exe`, `.pdb`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.ico`, `.zip`

## Template Ignored Folders

During project generation, these folders are not copied:
- `bin/`, `obj/`, `.vs/`, `.idea/`, `node_modules/`, `.git/`
